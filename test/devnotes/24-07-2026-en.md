### My thoughts on GNU/HURD 

**GNU/HURD** With its microkernel architecture dating back to the 1990s and being compatible only with `i386`, this project was doomed from the start—so just forget about it. When we run `sudo apt update`, all the stacks freeze; even if we say we’ve fixed that, we’re then faced with the duo of `Page Fault` and `Deadlock`—the kernel waits for the server, and the server waits for the kernel. If you look at the results, they’ve been tirelessly working on this for 30 years—while that’s commendable, the world doesn’t think so highly of the microkernel.
Microkernel architectures and projects are now written and used primarily for academic research at universities. Beyond that, they’re used in two main fields: aviation and healthcare. To be blunt: if the time spent on the microkernel had been devoted to monolithic kernels instead, Linux could be in a very different place today.
For now, my plan is to resolve the following two critical bugs in HURD by Monday (July 27) and create a `patch tag` to send to the GNU team:
1. `Mach IPC`: Under heavy load, IPCs freeze completely.
2. `Deadlock` & `Page Fault`: When a server in user space crashes or freezes, the entire system enters a circular deadlock, getting stuck in an infinite loop; sometimes this results in a `buffer overflow` or `kernel panic`.

Although it doesn’t concern us right now, the third critical issue is **incompatibility**. HURD still uses the i386-gnu architecture; even if these two critical bugs are fixed by Monday, migrating i386 compatibility to x86_64 looks like it will take the GNU Team another 10 years :)

### Mathematical Explanation (Theoretical)

 1) **Circular Deadlock and the Coffman Conditions** \
    A circular deadlock in the system occurs when the **Coffman Conditions** ($4/4$) are all satisfied simultaneously. The dependency matrix between the Kernel ($K$) and the Server/Translator ($S$):
    - **Dependency:** $K \rightarrow S$ (The Kernel is waiting for a response from the Server)
    - **Reverse Dependency:** $S \rightarrow K$ (The Server is waiting for page/memory allocation from the Kernel) \

    This situation forms a circular cycle ($C$) in a directed graph:

    $$C = \{K \rightarrow S \rightarrow K\}$$

    In a traditional Mach IPC, if the timeout or priority ceiling is not managed properly, the system’s wait time $T_{\text{wait}} \rightarrow \infty$ and the system stops responding.

  2) **IPC Queue Saturation (Queue Saturation & Little's Law)** \
     The locking of the message queue in `ipc_mqueue.c` can be modeled using Little's Law ($\lambda$ arrival rate, $W$ dwell time, $L$ queue length):

     $$L = \lambda \cdot W$$

     - When an intensive operation such as `sudo apt update` begins in the system, the arrival rate increases to $\lambda_{\text{peak}} \gg \lambda_{\text{normal}}$.

     - Because the cost of processing each message increases due to contention on the spin-lock/mutex, the waiting time $W$ grows exponentially.

     - When the queue capacity reaches the $L_{\max}$ limit, new messages cannot allocate memory (`ipc_kmsg.c`), and `Page Fault`s are triggered one after another.

## 1. `ipc_kmsg.c` Analizlerim (`ipc_kmsg_free`)

One of the most important functions we should focus on when examining the `ipc_kmsg.c` code is undoubtedly `ipc_kmsg_free()`—let's take a look;

```C
/* old version */

void
ipc_kmsg_free(ipc_kmsg_t kmsg)
{
	vm_size_t size = kmsg->ikm_size;

	switch (size) {

	    case IKM_SIZE_NETWORK:
		/* return it to the network code */
		net_kmsg_put(kmsg);
		break;

	    default:
		kfree((vm_offset_t) kmsg, size);
		break;
	}
}
```

### 1.1 Vulnerabilities and Errors in the `ipc_kmsg_free()` Function

1) **No Null Pointer Check for `kmsg`:** \
    If the `kmsg` call returns `NULL` due to a memory error or a crashed user-space server (translator), the `kmsg->ikm_size` line immediately triggers a **Kernel Panic** or a **circular Page Fault**.

2) **No Default Size Validation (`IKM_SIZE_NORMA` / Valid Sizing):** \
    In the `switch (size)` block, only `IKM_SIZE_NETWORK` is checked; everything else is unquestioningly passed to `kfree` under the `default:` branch. When a corrupted message size is received, `kfree` attempts to free memory of the wrong size; this corrupts the kernel zone memory and triggers an endless cycle of circular locks.

3) **Race Condition & Double Free:** \
    When `kmsg` is freed, the message’s state or any locks on it are not checked. Under heavy load (during `sudo apt update`), when multiple threads access the same message object, the same block is attempted to be freed multiple times (double free), leading to a `buffer overflow` or memory crash.

### 1.2 The `ipc_kmsg.c` Patching Process

The function must be designed according to the principles of defensive programming, based on the following logic:

```C
void
ipc_kmsg_free(ipc_kmsg_t kmsg)
{
	vm_size_t size;

	/* Early exit: NULL kmsg protection */
	if (unlikely(kmsg == IKM_NULL))
		return;

	size = kmsg->ikm_size;

	/* Network buffer offload */
	if (size == IKM_SIZE_NETWORK) {
		net_kmsg_put(kmsg);
		return;
	}

	/* Sanity check: Size bounds validation before kfree */
	if (unlikely(size == 0 || size > IKM_SAVED_MAX)) {
		printf("ipc_kmsg_free: corrupt kmsg size (%lu), leaking to prevent crash\n",
		       (unsigned long)size);
		return;
	}

	kfree((vm_offset_t) kmsg, size);
}
```

**What Did We Do?**

- `unlikely()` **Macro:** `kmsg == IKM_NULL` or corrupted size conditions are exceptional cases. We sped up the CPU pipeline by telling the compiler (GCC) during branch prediction that this path is unlikely to be executed.

- **Graded Early Exit (Guard Clauses):** We got rid of unnecessary `switch-case` and deep `if-else` structures. The code flows straight down.

- **Simple and Direct Logic:** If it’s a network message, return it and exit; if there’s a size issue, warn and exit; if everything is valid, call `kfree`.

### 2. My Analysis of `ipc_kmsg.c` (`ipc_kmsg_get()`)
While examining the `ipc_kmsg.c` code, the second major vulnerability that caught my eye was the `ipc_kmsg_get` function:

```C
// <<<<< original version >>>>>

/*
 *	Routine:	ipc_kmsg_get
 *	Purpose:
 *		Allocates a kernel message buffer.
 *		Copies a user message to the message buffer.
 *	Conditions:
 *		Nothing locked.
 *	Returns:
 *		MACH_MSG_SUCCESS	Acquired a message buffer.
 *		MACH_SEND_MSG_TOO_SMALL	Message smaller than a header.
 *		MACH_SEND_MSG_TOO_SMALL	Message size not long-word multiple.
 *		MACH_SEND_NO_BUFFER	Couldn't allocate a message buffer.
 *		MACH_SEND_INVALID_DATA	Couldn't copy message data.
 */

mach_msg_return_t
ipc_kmsg_get(
	mach_msg_user_header_t 	*msg,
	mach_msg_size_t 	size,
	ipc_kmsg_t 		*kmsgp)
{
	ipc_kmsg_t kmsg;
	mach_msg_size_t 	ksize = size * IKM_EXPAND_FACTOR; 

	if ((size < sizeof(mach_msg_user_header_t)) || mach_msg_user_is_misaligned(size))
		return MACH_SEND_MSG_TOO_SMALL;

	if (ksize <= IKM_SAVED_MSG_SIZE) {
		kmsg = ikm_cache_alloc();
		if (kmsg == IKM_NULL)
			return MACH_SEND_NO_BUFFER;
	} else {
		kmsg = ikm_alloc(ksize);
		if (kmsg == IKM_NULL)
			return MACH_SEND_NO_BUFFER;
		ikm_init(kmsg, ksize);
	}

	if (copyinmsg(msg, &kmsg->ikm_header, size, kmsg->ikm_size)) {
		ikm_free(kmsg);
		return MACH_SEND_INVALID_DATA;
	}

	*kmsgp = kmsg;
	return MACH_MSG_SUCCESS;
}

/*
 *	Routine:	ipc_kmsg_get_from_kernel
 *	Purpose:
 *		Allocates a kernel message buffer.
 *		Copies a kernel message to the message buffer.
 *		Only resource errors are allowed.
 *	Conditions:
 *		Nothing locked.
 *	Returns:
 *		MACH_MSG_SUCCESS	Acquired a message buffer.
 *		MACH_SEND_NO_BUFFER	Couldn't allocate a message buffer.
 */

extern mach_msg_return_t
ipc_kmsg_get_from_kernel(
	mach_msg_header_t 	*msg,
	mach_msg_size_t 	size,
	ipc_kmsg_t 		*kmsgp)
{
	ipc_kmsg_t kmsg;

	assert(size >= sizeof(mach_msg_header_t));
	assert(!mach_msg_kernel_is_misaligned(size));

	kmsg = ikm_alloc(size);
	if (kmsg == IKM_NULL)
		return MACH_SEND_NO_BUFFER;
	ikm_init(kmsg, size);

	memcpy(&kmsg->ikm_header, msg, size);

	kmsg->ikm_header.msgh_size = size;
	*kmsgp = kmsg;
	return MACH_MSG_SUCCESS;
}
```

### 2.1 Vulnerabilities & Weaknesses in the Code

Upon examining the functions, very serious integer overflow vulnerabilities dating back to the 1990s and **memory leak/boundary** control flaws stand out.

**Critical Vulnerabilities in `ipc_kmsg_get`**

- **Integer Overflow / Multiplication Overflow:**

```C
mach_msg_size_t ksize = size * IKM_EXPAND_FACTOR;
```
If the `size` value coming from user space is set too large, `(size * IKM_EXPAND_FACTOR)` results in a product that exceeds the `mach_msg_size_t` (unsigned int) limit and wraps around. `ikm_alloc` is called with `ksize`, which has been reduced to a smaller value (allocating a smaller amount of memory). However, immediately afterward:
```C
copyinmsg(msg, &kmsg->ikm_header, size, kmsg->ikm_size)
```
an attempt is made to copy using the original massive `size`. This immediately triggers a **Heap Buffer Overflow**, **Kernel Memory Corruption**, or **Circular Page Fault**!

- **Incorrect Freeing in Case of an Error (`ikm_free` vs `ipc_kmsg_free`):**
```C
if (copyinmsg(msg, &kmsg->ikm_header, size, kmsg->ikm_size)) {
    ikm_free(kmsg); // <-- HERE!
    return MACH_SEND_INVALID_DATA;
}
```
If the message size is smaller than the `IKM_SAVED_MSG_SIZE` limit, memory is allocated from the cache using `ikm_cache_alloc()`. However, when `copyinmsg` fails, `ikm_free(kmsg)` is called directly! When the buffer object retrieved from the cache is passed to the general allocator function, the cache structure is corrupted, leading to a chain reaction of memory locks. This must be cleaned up using `ipc_kmsg_free()`, which we just made bulletproof.

- **No Upper Size Limit Check for `copyinmsg`:** \
When user space sends an absurd size (e.g., 2 GB), it is passed to the kernel allocator **without being checked**.

### Final Version (`ipc_kmsg_get()`):

```C
/*
 *  Routine:    ipc_kmsg_get
 *  Purpose:    Allocates a kernel message buffer and copies user message.
 *  Author:     Alperen ERKAN (2026)
 */
mach_msg_return_t
ipc_kmsg_get(
    mach_msg_user_header_t  *msg,
    mach_msg_size_t         size,
    ipc_kmsg_t              *kmsgp)
{
    ipc_kmsg_t      kmsg;
    mach_msg_size_t ksize;

    /* 1. Alt sınır ve hiza kontrolü */
    if (unlikely((size < sizeof(mach_msg_user_header_t)) || 
                 mach_msg_user_is_misaligned(size)))
        return MACH_SEND_MSG_TOO_SMALL;

    /* 2. Üst sınır ve Integer Overflow koruması */
    if (unlikely(size > IKM_SAVED_MAX || 
                 size > (MACH_MSG_SIZE_MAX / IKM_EXPAND_FACTOR)))
        return MACH_SEND_NO_BUFFER;

    ksize = size * IKM_EXPAND_FACTOR;

    /* 3. Tampon tahsisi */
    if (ksize <= IKM_SAVED_MSG_SIZE) {
        kmsg = ikm_cache_alloc();
        if (unlikely(kmsg == IKM_NULL))
            return MACH_SEND_NO_BUFFER;
    } else {
        kmsg = ikm_alloc(ksize);
        if (unlikely(kmsg == IKM_NULL))
            return MACH_SEND_NO_BUFFER;
        ikm_init(kmsg, ksize);
    }

    /* 4. Güvenli kopyalama ve hata durumunda doğru kmsg temizliği */
    if (unlikely(copyinmsg(msg, &kmsg->ikm_header, size, kmsg->ikm_size))) {
        ipc_kmsg_free(kmsg); /* ikm_free yerine güvenli ipc_kmsg_free kullanımı */
        return MACH_SEND_INVALID_DATA;
    }

    *kmsgp = kmsg;
    return MACH_MSG_SUCCESS;
}

/*
 *  Routine:    ipc_kmsg_get_from_kernel
 *  Purpose:    Allocates a kernel message buffer for internal kernel messages.
 *  Author:     Alperen ERKAN (2026)
 */
extern mach_msg_return_t
ipc_kmsg_get_from_kernel(
    mach_msg_header_t   *msg,
    mach_msg_size_t     size,
    ipc_kmsg_t          *kmsgp)
{
    ipc_kmsg_t kmsg;

    assert(size >= sizeof(mach_msg_header_t));
    assert(!mach_msg_kernel_is_misaligned(size));

    if (unlikely(size > IKM_SAVED_MAX))
        return MACH_SEND_NO_BUFFER;

    kmsg = ikm_alloc(size);
    if (unlikely(kmsg == IKM_NULL))
        return MACH_SEND_NO_BUFFER;
    ikm_init(kmsg, size);

    memcpy(&kmsg->ikm_header, msg, size);
    kmsg->ikm_header.msgh_size = size;

    *kmsgp = kmsg;
    return MACH_MSG_SUCCESS;
}
```
